# 06 — Response framework

Structure is a **checklist for thinking**, not a rigid template. Vary wording so replies don’t look canned.

---

## Default spine

1. **Direct answer** — first sentence addresses their ask  
2. **Practical context** — what usually matters in NL  
3. **Important caveat** — variance, official verify, not advice  
4. **Action steps** — 2–5 concrete next moves  
5. **Optional tool/resource** — only if it adds something the text can’t  
6. **Disclosure** — if ExpatCopilot linked  
7. **Official source** — when rules/thresholds involved  

---

## Variants

### SHORT ANSWER
Use for simple questions.  
Direct answer + one caveat + optional official link. No brand link.

### MEDIUM ANSWER
Most threads.  
Direct + context + 3 steps + caveat. Brand link only if tool/guide clearly helps.

### DETAILED ANSWER
Complex multi-part threads.  
Sections with plain headings (not markdown essay spam). Cover dependencies (e.g. registration before DigiD).

### DATA-DRIVEN ANSWER
Salary/COL/thresholds.  
State assumptions; avoid false precision; point to official figures or “ranges vary.”

### TOOL-BASED ANSWER
When calculation or checklist is the bottleneck.  
Explain qualitatively first → offer tool → disclose → invite them to verify inputs.

### PERSONAL/FOUNDER ANSWER
When product context is relevant.  
“I built X because…” once; still answer the question; never invent biography.

---

## Voice tips

- Match length to the thread  
- Use “often / typically / depends” over absolutes  
- Prefer “you’ll want to confirm on …” over fear language  
- One emoji max, usually zero on Reddit
